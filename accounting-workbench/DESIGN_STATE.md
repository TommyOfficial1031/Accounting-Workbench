### 2.5 盈亏平衡与折扣分析（做给中心的人算利润，不是算回归）

**已确认：只做盈亏平衡分析，不做回归。**「线性回归拟合」是历史误称。

**单位口径（用户确认）**：`P0`（转运费原价）与 `P`（转运费现价）**一律按单公斤单价**，元/kg。

#### 模型（`shell-demo.html` 内 `regModel()`，测试与页面同源）

**口径最终版（2026-10-22 用户第三次举例定稿）：中心有两个利润点，政策就是这两个的组合。**

```
① 价差利润 = (P − C) × Z        可为负（现价低于成本就是在补贴）
② 杂费利润 = B                  纯收入，与货量无关
合计 L(Z)  = (P − C) × Z + B
利润率 r   = L ÷ (P × Z + B)

不亏本 L ≥ 0 的三种等价写法：
  ① 给定 Z、B → 折扣下限  d ≥ (C − B ÷ Z) ÷ P0
  ② 给定 d、B → 保本货量  Z ≤ B ÷ (C − P)（仅 P < C 时需要）
  ③ 给定 d、Z → 杂费下限  B ≥ (C − P) × Z
换算：在计划货量下，1 个百分点折扣 = P0 × Z ÷ 100 元
B = 0 时：d ≥ C ÷ P0，利润率恒为 1 − C ÷ P。

政策对比（用户 2026-10-22 定稿：**唯一一张图，X = 货量，Y = 利润**）：
  当前政策线   L(Z) = m × Z + B当前          m = 现价 − C
  调整后政策线 L(Z) = m调 × Z + B            m调 = P0 × d计划 − C
  水平基准线   L = 0                          （不是价格 C；C 只决定斜率）
  竖直参考线   Z = 计划承诺货量
  利润 / 利润率只在交点处标注，不单独占坐标轴。
```

**不要把 B 说成"被货量吃掉"**：B 是纯收入，数学上只是让利润线整体上移；
"补价差"只是同一笔账的另一种说法（`L = 价差 + B`）。

**用户那个例子（页面按这套公式算出来的就是这些数）**

`网点货量 150 吨、P0=0.5、P=0.3（6 折）、当前杂费 3000、C=0.35` →
按计划折扣 60%（与当前一致）：两条线重合，都过 **−¥4,500**；把计划折扣提到 66% ⇒ **0**（保本），提到 70% ⇒ **+¥3,000**（只剩杂费）。

| 项 | 值 | 说明 |
|---|---|---|
| ① 价差利润 | −¥7,500 | `(0.3 − 0.35) × 150000`，这块是亏的 |
| ② 杂费利润 | +¥3,000 | 纯收入（当前杂费没调整） |
| 合计 | **−¥4,500**（利润率 −9.37%） | 净亏 |
| 保本方案 A | 杂费提到 **¥7,500**（+4,500） | 折扣不动 |
| 保本方案 B | 折扣提到 **66.0%**（+6 个百分点，现价 0.3300） | 杂费不动 |
| 互换比例 | **1 个百分点折扣 ≈ ¥750 杂费** | `P0×Z÷100` |
| B=0 时 | 保本折扣 70.0%（=C÷P0），利润率 −16.67% | 只靠价格 |
| 计划折扣 66% | 计划利润 **¥0** | 保本点（含杂费） |

**利润率怎么变**：`r(Z)` 从「B 占比很大」一路降到 `1 − C÷P`——
所以「货量增长 → 利润率下降、利润值按斜率 m 线性变化」；`m > 0` 时利润值升，`m < 0` 时利润值降。

**关键性质（`_proto/check_regression.cjs` 逐条断言，31 条）**

| 编号 | 性质 | 意义 |
|---|---|---|
| A1 | `L(Z2) − L(Z1) === m·(Z2 − Z1)`；`L` 对 B 的偏导恒为 1 | 两个利润点线性相加，B 只做平移 |
| A2 | `d_min(Z)` 随 Z 递增、渐近 `C÷P0`；`d_min(Z保本) === d` | 保本约束的三种写法是同一件事 |
| A3 | `B = 0` 时 `d_min ≡ C÷P0`，且 `r ≡ 1 − C÷P` | 单纯用折扣价算的退化情形 |
| L2 | 计划折扣不变时两条线重合；改折扣只改斜率 `m调`，改杂费只改截距 | 政策对比图的两条线各管一件事 |
| L3 | 折扣提到 `C÷P0` 时 `m调 = 0`，计划利润 ≡ 杂费 | 折价换量的临界点 |
| T | `P = Σ现价 ÷ Σ结算重量`、`P0 = Σ原价 ÷ Σ结算重量`、`C = Σ车线 + 操作`（按省） | 表格取数的口径 |

#### 表格取数口径（2026-10-22 二次改版，用户定稿）

1. **表格取数是独立计算**：只认你选定的那 6 列字段（网点 / 公斤段 / 省份 / 结算重量 / 现价 / 原价）的**全量数据**，
   与分析页的时间范围、筛选条件**无关**（用户原话："和分析界面设置什么样的条件没有关系"）。
2. 入口顺序：**表格取数在前、默认**；手动输入保留。
3. 分组筛选条件：一个维度一行 = **取值区本身是下拉按钮**（点开勾选，chip + ▾）；**勾了值 = 按这些值组合展开卡片**（3 网点 × 2 公斤段 × 2 省份 = 12 张），一个值都不勾 = 合计一行；
   省份候选**跟随已选网点级联**（改网点后自动剪掉失效省份）；底部实时统计「命中 N 行 / M 组」；
   **没有「分组」勾选框**了（勾值即拆卡）；组合里没有数据的会被隐藏并在统计行注明。
4. 每组各算一套 `P0 = Σ原价 ÷ Σ结算重量`、`P = Σ现价 ÷ Σ结算重量`、`d = P ÷ P0`（自动、只读）。
5. **每组手填 4 个数**：车线成本、操作成本、计划调整折扣、计划承诺货量；`C = 车线 + 操作`。
6. **本轮不含杂费**（只在表格模式；手动模式仍保留 B）：`利润 = (P − C) × Z`，
   调整前用数据货量与当前 P，调整后用 `P0 × 计划折扣` 与计划承诺货量；`利润率 = (P − C) ÷ P`。
7. 合计 = 各组利润 / 货量 / 收入分别相加；汇算明细表列出每组 + 合计（无杂费列）。
8. 未填车线成本按 0 计、未填操作成本按 0.08 计、未填计划折扣按当前折扣、未填计划货量按数据货量。

#### 已确认口径（2026-10-22 用户举例定稿，不再询问）

1. **中心有两个利润点**：① 价差 `(P − C) × Z`（可为负，允许让价补贴）② 杂费 `B`（纯收入）。
   合计 `L = ① + ②`；政策就是这两个的组合。**表格模式本轮先只算 ①**。
2. **B 与货量无关**，不进单价，只让利润线整体上移；但在保本约束里可以顶替折扣：
   `d ≥ (C − B÷Z) ÷ P0` / `Z ≤ B÷(C−P)` / `B ≥ (C−P)×Z` 三种写法等价。
3. **C = 车线成本 + 操作成本**，是必填的**基准盈利线**。
4. **允许 B = 0**：此时保本折扣退化成水平线 `C÷P0`，利润率恒为 `1 − C÷P`。
5. **政策组合图**是 `(折扣, 杂费)` 平面上的保本直线；**利润–货量图**看货量增长对利润值/利润率的影响。
6. 模型是**线性**的（`L` 对 Z、对 B 都是线性的）；不做回归、不引入固定成本 F。
7. **表格模式的图**：每组一对线，**虚线 = 调整前、实线 = 调整后**（同组同色，组间不同色），
   每组在自己的计划承诺货量处画一段短竖线；不含 B 时所有线都过原点，**基准盈利线就是横轴**。

#### 保存语义：项目 / 历史记录到底存什么（2026-10-23 用户定稿）

**两个写入口**：① 用户点「保存」（Ctrl+S）；② **没点保存就退出**（关窗口 / 关应用）。
两者的区别只有一个字段 `saved_kind`：手动保存 = `manual`，退出时自动保存 = `auto`（列表里带「自动保存」标签）。
**同一条项目只存一行**：已有 `id` 就覆盖更新，只有从没保存过才新建 `未命名N`（N = 现有未命名最大序号 + 1）。

##### 一条项目记录（= SQLite `projects` 一行，也是历史记录列表的一项）

| 字段 | 类型 | 来源 / 规则 |
|---|---|---|
| `id` | uuid | 首次保存时生成，之后不变 |
| `name` 项目名 | string | 新建时必填；自动保存时取 `未命名N`；可重命名 |
| `creator` 创建人 | string | 新建时必填；**第二次起自动沿用上次**；自动保存也沿用它 |
| `source_path` 文件路径 | string | 粘贴/浏览/drag 进来时记下；合并项目记「合并：A + B」 |
| `source_type` / `sheet_name` | string | xlsx / xls / csv + 实际读的 Sheet 名（多 Sheet 时提示过） |
| `created_at` 创建时间 | datetime | **首次保存时定格**，之后永不改（`YYYY-MM-DD HH:MM:SS`） |
| `updated_at` | datetime | 每次保存（含自动保存）刷新 |
| `last_opened_at` 最近打开时间 | datetime | **打开项目时**写；只在项目管理里展示，**不参与排序** |
| `saved_kind` | `manual` / `auto` | 决定「自动保存」标签与「手动创建 / 自动保存」筛选 |
| `has_result` 是否有分析结果 | bool | 三个工具页**任一**出过结果就置 true，之后不再回落 |
| `row_count` / `col_count` | int | 表格维度，列表里显示「12,480 × 44」 |
| `data_file` | path | `projects/<id>/data.parquet`（保存后的当前表格状态） |
| `state` 三个界面的操作快照 | JSON | 见下表；**只存输入，不存结果数值**（结果一律重算） |

##### `state`：三个工具页各存什么

| 界面 | 存的内容 |
|---|---|
| **分析**（`analysis`） | 时间范围 `{field, start, end}`；筛选条件 `[{field, op, values[], value2}]`；指标 `[{field, agg, op, alias}]`；占比配置 `[{mode, customDims}]`；输出方式 `table \| chart`；图表 `{type, xSel:{维度: [取值]}, y:[指标], title, legendNames}` |
| **一键算 / 看板**（`board`） | 网点多选 `nets[]`；口径 `{excl, src}`；时间 `{range: 本月/上月/自定义, from, to}`；分组维度 `dims[]`；维度取值 `dimValues{维度: [取值]}`；启用的区块 `features[]`；对比图 `{metrics[], type, split}` |

##### 动作 → 写入规则

| 动作 | 写什么 |
|---|---|
| 点「保存」 | 覆盖同 `id` 一行；`updated_at` = now；`created_at` / `last_opened_at` **不动**；`saved_kind = manual` |
| 没保存就退出 | 有 `id` → 同保存；无 `id` → 新建 `未命名N`，`saved_kind = auto`、`has_result` 沿用当前值 |
| 打开项目 | 只写 `last_opened_at` = now（**不动 `updated_at`**，所以不会改历史记录的排序），不产生新版本 |
| 删除项目 | 删 `projects` 行 **+ `projects/<id>/` 整个目录**（data.parquet、result.json）；历史记录同步消失 |
| 合并项目 | 生成**一条新项目**（`manual`，`source_path` 记「合并：A + B」），原项目保留 |
| 清理未命名 | 批量删除 `saved_kind = auto` 且名称为 `未命名N` 的行与目录 |
| 出结果 | 三个工具页任一算完 → `has_result = true`（列表「有」、历史「有结果」、行内「分析」按钮解禁） |

##### 历史记录存什么

历史记录**不是独立存储**，就是 `projects` 表按 **`updated_at`（最后保存时间）倒序**的视图：

- 每项显示：项目名 · 「行 × 列」· 创建人 · **最后保存时间** · `has_result` 的「有结果」chip · `auto` 的「自动保存」chip；
- 排序：**`updated_at` 倒序**——「退出自动保存」也算一次保存，所以它会立刻顶到最上面；
- 筛选：项目名 / 创建人模糊匹配 + **创建时间**范围（按 `name`、`creator`、`created_at` 查询，注意筛的是创建时间、排的是保存时间）；
- 分页：每页 8 条；
- 保留策略：`auto` 且 `未命名N` 的项目最多留 20 条，超出按 `updated_at` 最旧的自动清掉（防止无限堆积）。

##### 两个页面的排序口径（2026-10-23 用户定稿）

| 页面 | 排序键 | 方向 | 说明 |
|---|---|---|---|
| **项目管理** | `created_at` 创建时间 | 倒序（最新建的在最上） | 同一时刻创建的，用 `updated_at` 兜底，保证顺序稳定 |
| **历史记录** | `updated_at` 最后保存时间 | 倒序（最近保存的在最上） | 手动保存与「未保存直接退出」的自动保存**一视同仁** |

对照原型：项目管理多了一列「最近打开」（`last_opened_at`，只展示不排序）；
历史记录条目显示的是「最后保存」，与排序键一致。

##### 原型阶段的落地方式（下一步实现时用）

先落 `localStorage`（一个 `awb.projects` 数组 + 当前 `awb.currentId`），字段与上表**完全一致**，
这样以后换成 SQLite 只是换存储层，前端读写逻辑不用改。

## 5. 看板语义

- 「对比图表」与三个矩阵区块**互斥**（`features` 多选决定显示哪几个 section）。
- **多图默认拆分**：每组（省份 / 网点 / 网点×省份）一张小图，图内 = 选中指标数条系列；
  切到「合并」则回到单图 `min(6 组, 行数) × 选中指标数` 条系列。饼图只有一个圆，**不参与拆分**。
- 饼图用**组货量**（只用第一个对比指标）：扇区内写百分比，引导线标签写**完整分组名 + 占比**，
  标签做垂直防重叠；扇区太窄（< 约 12.6°）只留引导线，硬塞会压字。
- 对比图表整体按 **130% 宽度**渲染，超出容器时在 `.chart-scroll` 内横向滚动（用户要求「放大 30%」）。
- 图表颜色**不要过饱和**（用户明确反馈）。
- **对比指标共四个**：`货物流向占比`（同组货量 ÷ 行合计）、`货物流向数据`（= 结算重量求和，绝对 kg）、
  `公斤段折扣`、`公斤段单价`。选了「货物流向数据」时纵轴按 kg 计（`cmpShort`），
  若同时选了占比/单价，标题会提示「量纲不同，建议分开看」。
- 合并模式图 `width:100%` 且最大 1180px、水平居中（**不要再用百分比宽度 + max-height**，会产生 letterbox 把内容挤到右边）。
- 所有图表容器带 `data-zoom`，双击空白区放大；双击标题 / 图例仍是改名。
- 分组维度选项：`省份` / `网点` / `网点×省份`，配合 `dimValues` 过滤。
  **候选值必须来自已选网点**（`boardDimSources()`）：候选网点 = 当前选中集，
  候选省份 = 这些网点实际覆盖的省份；网点选择变化时 `pruneDimValues()` 剪掉失效取值。
  演示数据里每个网点只覆盖约 76% 的省份，所以这个差异**在原型里看得见**。

## 7. 环境与坑（踩过的，别再踩）

| 坑 | 处理 |
|---|---|
| **B 的口径反复改过 3 次** | 最终结论：B 与货量无关（不进单价），但**必须进保本约束**——`d ≥ (C−B÷Z)÷P0` 就是它的直接后果。别再以"B 与货量无关"为由把曲线抹平成一条水平线 |
| **X 轴语义** | 用户要的是「结果表按维度组合过滤」：一级 = 分组维度、二级 = 该维度**已有的**取值、多维度勾选 = 交集；**不是**「按任意字段重新聚合」。2026-10-22 理解错过一次，白做一轮 |
| **表格取数里 B 只计一次** | 按省分组时每组利润 = `m × 该组货量`（不含 B），只有合计行加 B；否则会按省重复计 B |
